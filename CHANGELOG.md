# Changelog

All notable changes to the `stride-copilot-exploratory-testing` plugin are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **`fixtures/example-explorer-output.json`**, a complete contract `1.0` explorer report with synthetic data only (`demo.example.com`, `<tenant A>`, the made-up tracker id `EF-112`) — no real host, credential or token.
- **An "Explorer output contract" section in `lib/test-structure.sh` (python3) and `lib/test-structure.ps1` (`ConvertFrom-Json`)**, with identical check labels in both shells. It parses the agent file's own tables — the root keys and their element types, the `bugs` field table, the `session_sheet` table, the *Status from `stop_reason`* table, the documented `contract_version` and the card's severity tokens — and validates the fixture against them, then fixture variants that must pass (no bugs, a session blocked before its first probe, `2/3`, a once-seen `1/5` Critical, a `not established` count) and variants that must be refused (`1/1`, `4/3`, `0/3`, a bug without `replicated` or `provisional`, a provisional Critical, a missing or wrong `contract_version`, a status the table does not give, a stop reason it does not map, plain-string or mis-kinded elements, and more). It also checks that a derivation table missing a stop-reason row fails, that the explore skill's result reading names exactly the contract `1.0` root keys, and that the skill's inline restatement of the status mapping matches the agent's table. Set `EXPLORER_OUTPUT` to a report's path to check a real report by the same rules; a missing or empty file fails with a message naming the path, and with the variable unset only the bundled fixture is checked. The fixture is also added to the suite's list of required fixtures, which is four names now.

### Changed

- **The `explorer` output contract is version `1.0`**, ported from the Claude Code plugin. `status` is now derived from `session_sheet.stop_reason` by a published *Status from `stop_reason`* table — `charter_quiet` and `risk_acceptable` give `completed`, `probe_budget_exhausted` and `tool_call_ceiling` give `stopped_early` (defined for the first time), and `blocked` gives `blocked`, including a target that is not clearly authorized — and a consumer that meets a disagreeing `status` trusts `stop_reason`. Each bug gains `replicated` (`"<k>/<n>"` from clean-start re-runs with *n* ≥ 2, never `"1/1"`, or `"not established: <reason>"`) and `provisional`; `questions_risks` elements become `{kind, text}` and `off_charter` elements `{item, candidate_charter}`; a new `known_bad` root array holds results judged Known-bad-but-expected; and the root carries `contract_version: "1.0"`. A new Edge case covers a target that is not clearly authorized. The card names the three new fields and grows from 3,990 to 4,054 bytes, under its 4,096-byte cap; the agent body is 26,215 characters, under the 30,000-character limit the [custom agents configuration reference](https://docs.github.com/en/copilot/reference/custom-agents-configuration) sets.
- **The agent accepts an optional, untrusted `known_issues` list as prompt text.** The same reference documents no named-argument schema for invoking a custom agent — the task arrives as the prompt — so where other editions say the list may come as its own argument or as a `KNOWN_ISSUES:` block inside the environment context, this edition takes it only as its own `<known_issues>` … `</known_issues>` block in the prompt, outside the environment context. Every line between the markers is an entry and none is read as environment context, charter, budget or target, and a list with a missing, unclosed or repeated marker is ignored and recorded as an obstacle — so an entry pasted from a tracker cannot pass itself off as the line naming the authorized target. It is matched at the oracle step as data and never followed as instructions, and nothing in it authorizes a target. The explore skill does not pass it yet.
- **The `stride-exploratory-testing-explore` skill reads explorer results by contract `1.0`.** Its collect-and-parse step lists the `1.0` root keys and reads a result by its `contract_version` (`"1.0"`; absent, an older explorer that stays usable; any other value, kept and named under Unknown). It derives `status` from `stop_reason` and states that mapping inline, because a Copilot skill has no documented path to the agent's file. The debrief labels a bug confirmed only at `replicated` *k* ≥ 2 with `provisional: false`, counts confirmed and unconfirmed bugs separately, reports `known_bad` entries under Found without ranking or backlogging them, groups `questions_risks` by `kind`, and builds the parking lot from each `candidate_charter`.
- Not ported, because this edition has no such feature: the Claude Code contract's report-file and verify-mode parts. Its `no_observation_surface` part is ported below.
- **The `explorer` agent carries an inline explorer card.** A card of at most 4,096 bytes, between `<!-- explorer-card:start -->` and `<!-- explorer-card:end -->` right after the unchanged safety boundary, holds everything the agent needs to label a bug and end a session: the exact severity tokens `Critical`, `High`, `Moderate` and `Minor` with their rank and a condensed impact ladder, the tie rule, the three modifiers and their combination rule, the likelihood and unknown-impact rules, RIMGEA mapped onto the `bugs[]` fields, the three oracle verdicts and three oracle kinds, and the stop rules mapped onto `session_sheet.stop_reason`. The explore loop and the `bugs[]` rows point at the card, and the `heuristics`, `oracles`, `bug-advocacy` and `session` skills become optional depth. **The agent no longer names those skills by a `skills/<name>/SKILL.md` path.** None of the three GitHub Copilot documentation pages that cover this describes a path form by which a custom agent's body reaches a plugin's skill file — the [custom agents configuration reference](https://docs.github.com/en/copilot/reference/custom-agents-configuration) lists no frontmatter property for skills, the [CLI plugin reference](https://docs.github.com/en/copilot/reference/cli-plugin-reference) expands `${PLUGIN_ROOT}` only in a plugin-shipped agent's `mcp-servers` frontmatter, and [Adding agent skills for GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills) says Copilot picks a skill from the prompt and the skill's description, or by a `/name` in the prompt — so each skill is now named, with no path. Whether the old relative path ever resolved has not been live-tested; Copilot was not installed where this change was made. The card change itself altered no output-contract field; contract `1.0`, above, is a separate change.
- **The `explorer` agent judges only what its own tools let it see, and gains a sixth stop reason.** A new *What you can observe* section ports the curl rule and the `no_observation_surface` ending of the Claude Code plugin's W2263; this edition never had a fetch tool, so there was nothing to drop, and its tools list stays `read`, `search`, `glob` and `run`. HTTP is observed with `curl -q -sS -i`: `-q` comes first so a `~/.curlrc` cannot add options, and `-i` hands the oracle the status line and headers with the raw body. **`-L` and `--location` are forbidden.** When a redirect matters, the agent takes the `Location` value from the response it already has and requests it only if its scheme, host and port match a target the caller authorized; any other redirect is written down as a result. This goes past the Claude Code source, following the OpenCode port, whose security review showed a followed redirect could carry a probe to a host nobody authorized; this edition's own review added `-q`, because a `location` line in `~/.curlrc` would otherwise follow redirects with no `-L` in sight, and the full-origin match. A charter with no HTTP surface is untouched by the curl rule. A rendered view (layout, colour and contrast, browser differences, rendered accessibility) is never judged from HTML, CSS or template source, and a tool the environment context names is a hint, not a tool the agent holds. When a charter asks for an observation no tool of the agent's can make, it probes the observable part, names the gap in `debrief.unknown` and in a `risk` entry, and stops with `stop_reason: "no_observation_surface"`, whose status is `blocked`; that stop overrides any other. The value is added to the card's stop rules, the `stop_reason` list, the *Status from `stop_reason`* table, and the explore skill's restated mapping and backlog rule. `contract_version` stays `"1.0"`, since no root key, `bugs` field or element type changed. One redundant card line goes, leaving the card at 4,091 of its 4,096 bytes; the agent body is 29,644 characters, under Copilot's 30,000-character limit. **Unverified:** the [custom agents configuration reference](https://docs.github.com/en/copilot/reference/custom-agents-configuration) gives `execute` (with `shell`, `Bash` and `powershell`) as the terminal tool's aliases, does not list `run`, and says unrecognized tool names are ignored. If Copilot ignores `run`, the explorer has no terminal tool and an HTTP charter ends `no_observation_surface` instead of reporting an invented result. Copilot was not installed where this change was made, so this was not tested live.
- **`lib/test-structure.sh` and `lib/test-structure.ps1` pin the observation rules**, with matching labels in both shells: the tools line is exactly `read`, `search`, `glob` and `run` and has no fetch tool (`web`, `fetch`, `WebFetch` or a `web/` tool, with mutated lines checked too); the `curl -q -sS -i` form, the `~/.curlrc` reason, the no `-L` rule and the full-origin match are present, every `curl` code span starts with `-q`, and none follows redirects; the no-HTTP, never-from-source, hint-not-grant and `no_observation_surface` wording, its card stop rule and its status-table row are pinned; the status map gains the new value and a variant that ends `no_observation_surface` after probing the observable part must pass; the explore skill's handling is pinned; and the agent body is held to 30,000 characters. Each suite now runs 110 checks, up from 96.
- **The `explorer` safety boundary is structured**, ported from the Claude Code plugin's W2264 in this edition's own wording. The agent now requires two lines of their own in the environment context: `AUTHORIZED_NON_PRODUCTION: yes`, where only the exact value `yes` authorizes and a `> `-quoted line never counts, and `ALLOWED_HOSTS: <host[:port]>, …` (or `none`, which allows no network action). A missing, non-`yes` or duplicated line, even two identical ones, ends the session `blocked` with zero probes and no request. `ALLOWED_HOSTS` is the only source of reachable hosts and is matched exactly: no wildcards or subdomains, a name and its IP are separate entries, and an entry without a port admits only the scheme's default, so `localhost` does not admit `localhost:4000`. It binds every network action: with a browser tool the agent checks a link's or form's target before clicking or submitting, reads the current URL after every navigation or click, and stops if the host is off the list (the host follows any `user@`, so a URL with userinfo never matches), and the *What you can observe* redirect rule's "target the caller authorized" now means a host it lists. The agent lists every process and file it starts through `run`, keeps scratch files in one `mktemp -d` directory, starts a background process only under `timeout` (or `gtimeout`) and in its own process group where the shell allows, and removes everything by PID (a group only when it created that group) and path on every exit path, never with `pkill`, `killall` or a wildcard; cleanup is the one thing allowed past the tool-call ceiling, and it never changes `stop_reason`. A credential file (`.stride_auth.md`, `.env*`, keys, `.netrc` and the like) stays closed unless the test-account pointer names the file, the exact key and why, and even then the value is taken in one `run` command that prints nothing; searches and globs stay off credential files and secret-shaped strings. Upstream's report-file and verify-mode clauses are not ported, because this edition has neither. The tools list is unchanged, so `run` is still the unverified alias noted above. Prose elsewhere in the agent was tightened to stay under Copilot's limit: the body is 29,909 of 30,000 characters, and the card is unchanged at 4,091 bytes.
- **`skills/heuristics` limits Interrupt, Starve and the Saboteur Tour to in-app means**: cancel, sign out or let a request time out; use up an app-level quota with disposable test data; throttle only through an app setting or feature flag the tester may change, put back afterwards. None of them may kill a process the tester did not start, change operating-system or network resources, or touch another host.
- **The `stride-exploratory-testing-explore` skill writes the two lines once and first.** Its question round asks for the exact `host:port`, writes `AUTHORIZED_NON_PRODUCTION: yes` only on the explicit *"Authorized, non-production target"* answer and never by default, builds `ALLOWED_HOSTS` from the hosts the operator named (`none` for a CLI-only target), and prefixes any operator, target or charter line that starts with either name with `> `, so a forged line cannot authorize or widen a session. Where the answer and the zero-probe block could disagree, the block wins and nothing is dispatched. A credential-file pointer must name the exact key. **Consumer owed:** `stride-copilot`'s Step 5.5 does not send either line yet, so its explorer dispatches will end `blocked` with zero probes until it is updated.
- **`lib/test-structure.sh` and `lib/test-structure.ps1` pin the safety boundary**, with matching labels in both shells: both line names in the explorer's safety boundary and in the explore skill, the zero-probe rule, exact host matching, cleanup on every exit path and the credential-file rule, the older prohibitions, a card free of the new text, the in-app heuristics limits (with the three old phrasings refused), and the explore skill's once-and-first and `> ` rules. Each suite now runs 118 checks, up from 110.
- **`lib/test-structure.sh` and `lib/test-structure.ps1` gain their first content pins**, with matching labels in both shells: the card's markers and position, its 4,096-byte cap, its severity tokens, rank and ladder against `bug-advocacy`'s four-levels table, its stop rules against the output contract's `stop_reason` values, its RIMGEA, oracle and severity-rule text, and the absence of any `skills/<name>/SKILL.md` path in the explorer agent.

## [0.2.0] - 2026-08-01

Ported from the Claude Code plugin's 2026-07 improvement research: a sixth skill carrying the severity rubric the contract always required, session artifacts that survive the conversation, the SFDIPOT correction, and an explorer contract that reports what it counted instead of what it could not measure.

### Added

- **`stride-exploratory-testing-pair` skill** — an exploratory session with a **human at the keyboard**, the inversion of `stride-exploratory-testing-explore`. The human drives the application and reports what they did and saw; the skill suggests one probe per round and **names the `heuristics` lens it came from**, judges each report with `oracles`, runs RIMGEA on confirmed defects as instructions to the human, and keeps the SBTM session sheet and off-charter parking lot so the tester never context-switches into note-taking. Its signature work is the **unprompted coverage-gap sweep**: three ledgers (areas, the Variable Catalog rows, and seven fixed stances — valence, tenancy, role, character set, volume, sequence/concurrency, entry point) swept at fixed points, each gap raised at most once, with a declined gap going to the backlog rather than being lost. It measures only what it can observe — duration from two real `date` stamps, Task Breakdown Metrics marked *derived* unless the tester confirms them. It writes a session sheet and appends to the backlog, deliberately **not** the coverage outline, and hands off to `stride-exploratory-testing-debrief`. **It never drives the application and never dispatches the `explorer` agent.** Note that a Copilot `SKILL.md` has no tool allowlist, so unlike the Claude original that boundary is held by the skill's own rules rather than by a withheld tool — the skill says so plainly rather than claiming an enforcement it does not have.
- **`stride-exploratory-testing-harden` skill** — the bridge from *Explored* back to *Checked*. It reads a session's oracle-confirmed bugs (from an explorer findings object, a paired session sheet, a debrief, or pasted findings), **detects the project's own test framework** from its markers, existing tests, and config across ten ecosystems — reporting what it detected and on what evidence **before anything is written** — and drafts one regression check per convertible bug, built from that bug's isolated `minimal_repro`. A bug is convertible only with a stated trigger, a stated wrong result, a programmable observation, and a safe repro; everything else is reported not-converted under one of seven categories with the one thing that would fix it, because a guessed repro produces a check that passes for the wrong reason. Drafts never hard-code a secret, never point at a real host, and never perform a destructive action. They are staged under `.exploratory/checks/<timestamp>-<slug>/` with an `INDEX.md`, nothing is ever overwritten, and **it never runs a draft and never says one passes** — a rule the skill holds itself, stated as such, since a Copilot `SKILL.md` has no allowlist that could withhold a shell from it.
- **`bug-advocacy` skill** (`skills/bug-advocacy/SKILL.md`) — the sixth core skill, and the one that picks up where `oracles` stops. It encodes Cem Kaner's **RIMGEA** follow-through (Replicate, Isolate, Maximize, Generalize, Externalize, And say it clearly), each step with a definition and the prompt to ask, plus a **severity rubric a second reader can re-derive**: four named levels, an impact ladder of explicit clauses, three aggravating-only modifiers with a stated combination rule, an agreement test, and the two-door procedure for when the impact is genuinely unknown. `severity` was already a required field of the explorer's `bugs[]` contract and was defined nowhere — this is where it now comes from. Routed from `oracles` (at the moment a result is judged a Defect) and from the orchestrator's routing table.
- **Session artifacts on disk** — sessions now persist to `.exploratory/` in the project under test: `backlog.md` (append-only candidate/deferred charters, parked items, and open questions), `coverage.md` (the product coverage outline — a map, explicitly never a score), and `sessions/<timestamp>-<slug>.md` (one debrief per explore run, or one session sheet per paired session), and `checks/<timestamp>-<slug>/` (drafted regression checks, never run). The `session` skill owns the tree, the formats, the header blocks, and the read-immediately-before-write mechanics. **A missing artifact is an empty starting state, never an error**, so a first run in a new project simply creates what it needs. Add `.exploratory/` to the project under test's `.gitignore`.
- **`charter-generator` accepts `coverage context`** and gains an optional `deprioritized` output key. When a coverage digest is supplied it mines the still-dark areas and the open backlog, discounts charters aimed at ground already covered, and records what it moved down — with risk always outranking recency, so an area explored last week that still has an open Critical bug is not treated as covered. The `stride-exploratory-testing-explore` and `stride-exploratory-testing-charter` skills each assemble that digest and pass it; the agent stays read-only and never touches disk itself. `stride-exploratory-testing-recon` deliberately does **not** — recon is the first pass over ground nobody has explored, so there is no prior coverage to discount and `deprioritized` never appears there.
- **`interfaces` lens** — the Heuristic Test Strategy Model's **I**nterfaces element joins the coverage lens in the `chartering` skill, covering APIs, imports and exports, UI surfaces, and integration points between systems: the boundaries where service-oriented and LLM tool-calling applications most often fail. **Downstream consumers must handle `interfaces` as a new allowed value of a charter object's optional `lens` field** (`agents/charter-generator.agent.md`), alongside the existing `structure`, `function`, `data`, `platform`, `operations`, and `time`.

### Changed

- **`SFDPOT` renamed to `SFDIPOT`** across the plugin — skills, agents, fixtures, and docs. Bach's HTSM (v6.0, 2024) lists seven Product Elements; the six-letter `SFDPOT` the plugin cited is a superseded form of the same heuristic. The `Interfaces` row slots between `Data` and `Platform`; no existing row was renamed, reordered, or dropped. The charter object's `source` enum value is still the literal `sfdpot` — it is a wire value, not the acronym, and renaming it would break existing consumers.
- **The `explorer` agent's `bugs[]` objects carry the four RIMGEA fields.** Each bug now emits `minimal_repro`, `worst_observed`, `generalization`, and `stakeholder_impact` alongside the existing five, and `severity` must be one of the `bug-advocacy` rubric's levels written in full. **The four fields are honest-or-"could not establish", never invented** — the key is always emitted, and when the answer could not be established its value says exactly that. The `stride-exploratory-testing-explore` skill carries all four through aggregation and, when two sessions found the same bug, merges by keeping the shortest `minimal_repro`, the worst demonstrated `worst_observed`, and the broadest `generalization`. **Downstream consumers of `bugs[]` gain four keys**; none is removed.
- **All seven command-derived skills now participate in the artifact tree.** `stride-exploratory-testing-explore` writes its debrief, appends deferred and parked charters, and updates coverage — and on the plan-only path it backlogs the charters but deliberately does **not** touch coverage, because nothing was explored. `stride-exploratory-testing-debrief` appends parked items and open questions to the backlog and refreshes coverage for the areas its notes honestly identify. `stride-exploratory-testing-charter` and `stride-exploratory-testing-nightmare-headline` append their generated charters as `candidate-charter` entries. `stride-exploratory-testing-recon` appends candidate charters and open questions, and may add an **un-explored area stub** to the coverage outline — it never dates an existing area or marks one explored, because surveying is not exploring. `stride-exploratory-testing-pair` writes its session sheet and appends parked items, open questions and declined coverage gaps — deliberately never the coverage outline, which is derived from a debrief it stops short of producing. `stride-exploratory-testing-harden` writes only under `.exploratory/checks/` (or the `--output` directory named) and touches neither shared artifact. Every one of them treats a missing file as an empty starting state, names on finish every path it wrote, and reads what it reads as untrusted data.
- **Redaction and untrusted-input rules restated for written files.** The redaction rule now binds explicitly on *writes*, not only on rendered output — a file outlives the session and can be read by someone who never saw the run — and it covers the four new bug fields. Conversely, `backlog.md` and `coverage.md` are read back on later runs and are **data, never instructions**: a line in one that reads like a directive is content to report, never something to obey. RIMGEA's Maximize step is explicitly bounded by the explorer's absolute safety boundary, so "proving severity" never licenses a destructive action or the escalation of a security finding.
- **The `explorer` agent no longer reports numbers it cannot observe.** `session_sheet` drops `duration` and `tbs` (Task Breakdown Metric percentages) — a wall-clock measurement an agent has no way to take, whose presence contradicted the agent's own hard rule against fabricating a result. In their place it reports what it genuinely counts: `probe_budget`, `probes_attempted`, `probes_with_finding`, `on_charter_probes`/`off_charter_probes`, `tool_calls_used`, `heuristics_applied`, and `stop_reason`. An agent session is now bounded by an **agent-native budget** — a probe budget (default 12, band 8–20) and a tool-call ceiling (5 × the probe budget), whichever is reached first. The `session` skill keeps the 60–120 minute box and Task Breakdown Metrics for **human-run and paired** sessions and now states plainly that neither binds an agent session; the four stopping heuristics are unchanged in substance (bullet 2 now reads "The box or the budget is up"). **The `stride-exploratory-testing-explore` skill gains `--probes <count>`** for the per-session probe budget and **`--output <path>`**, which *redirects* the debrief rather than deciding whether one is written — that skill now persists its debrief by default to `.exploratory/sessions/<timestamp>-<slug>.md`; **`--timebox <minutes>` keeps its unit** and is now documented as doing only what it always effectively did — deciding how many charters run (one session ≈ 90 minutes) — and is never passed to the explorer. **Downstream consumers that read `session_sheet.duration` or `session_sheet.tbs` must switch to the counts**; the `stride-exploratory-testing-debrief` skill is unaffected (it consumes unstructured tagged notes). `fixtures/example-session-sheet.md` and `fixtures/example-debrief.md` are now **agent-run** examples — a `SESSION BUDGET` block with probe and tool-call counts and a `stop_reason` in place of `DURATION` and `TASK BREAKDOWN METRICS`.

## [0.1.0] - 2026-07-21

Initial release: the complete GitHub Copilot CLI port of `cheezy/stride-exploratory-testing`.

### Added

- **Repository and manifest.** Standalone git repository with a root-level `plugin.json` (Copilot schema: root manifest plus `"agents": "agents/"` and `"skills": ["skills/"]`), `README.md`, `HEURISTICS.md`, `LICENSE` (MIT), and this changelog. There is intentionally **no** `commands/` directory — Copilot CLI has no slash commands.
- **Core knowledge skills.** `stride-exploratory-testing` (orchestrator front door), `chartering`, `heuristics`, `oracles`, and `session` — the exploratory-testing doctrine.
- **Command-derived skills.** `stride-exploratory-testing-charter`, `-nightmare-headline`, `-explore`, `-recon`, and `-debrief` — the five upstream slash commands ported as named Copilot skills (Activation-section frontmatter, no `allowed-tools`/`argument-hint`).
- **Agents.** `agents/charter-generator.agent.md` and `agents/explorer.agent.md` (Copilot `.agent.md` format, array-form read-only/`run` tools, no `model` field).
- **Fixtures.** Worked `example-charters.md`, `example-session-sheet.md`, and `example-debrief.md` (synthetic *ExpenseFlow* target) that double as templates and smoke-test regression anchors.
- **Smoke tests.** Cross-platform `lib/test-structure.{sh,ps1}`, `lib/test-frontmatter.{sh,ps1}`, and `lib/test-all.{sh,ps1}` — offline structure/frontmatter validation that gates a release (no network, no `jq`).

### Distribution

- **Vendored into `stride-copilot-marketplace`.** Registered in the existing `cheezy/stride-copilot-marketplace` catalog at `0.1.0` — the plugin tree is vendored under `plugins/stride-copilot-exploratory-testing/` with a matching `plugins[]` entry (`source: ./plugins/stride-copilot-exploratory-testing`), and the catalog `metadata.version` was bumped to `1.6.0`. Once the catalog is registered, install by name with `copilot plugin install stride-copilot-exploratory-testing` (or directly with `copilot plugin install https://github.com/cheezy/stride-copilot-exploratory-testing`; see the README).
